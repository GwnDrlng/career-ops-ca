The problem

The ≥3.7 lane spends real money on Opus 4.8: judge → grounding-check, and a failing judge triggers up to two revise-and-re-judge retries. One application can fan out to 4–6 Opus calls, so a routing bug or retry loop could quietly burn a month's budget in an afternoon. Cost is invisible until the bill arrives, so it needs a hard automatic stop, not a dashboard you remember to check.

The core invariant: one chokepoint, gate-before / record-after

Every Opus call goes through a single function, opus-call.mjs → callOpus(). Nothing calls claude -p directly. That chokepoint checks the budget before the spend and records actual cost after it, so the ledger is always the source of truth and any new caller inherits every ceiling for free.

Four ceilings, three shapes, each matched to what it protects

5-hour token block
rolling 5h · trips at 75%
Rolling window matches Anthropic's usage block, which is what actually refills.
Weekly token allowance
rolling 7d · trips at 60%
Same reasoning, weekly grain.
Monthly cost cap
calendar month · trips at 75%
Anchored to the 1st (billing-aligned). A % ceiling leaves headroom to finish in-flight work by hand.
Per-application cost cap
all-time, one job_id · hard 100%
A per-item budget, not a buffer on a shared pool, so it's a hard line, scoped by a grouping key in the ledger.

Security & Governance

The steps that keep the cloud plane blind to your identity and every decision traceable.

Security

No secrets in the cloud
least-privilege boundary
The cloud holds no PII and no submit credentials. The grader sees only a de-identified digest.
Secrets stay on-prem
macOS Keychain
Slack tokens, portal logins, and sensitive answers never leave your machine.
Untrusted input as data
sanitize-jd.mjs
Job text is stripped of invisible/bidi characters and prompt-injection patterns before any model call.
No invented answers
vault.mjs
Work-auth, salary, and EEO fields fill only from pre-approved entries, or get flagged for you.

Governance

Config, not code
guardrails.yml
Every threshold is one reviewable diff, never a script edit.
Versioned scoring
prompt-version.mjs
Each score is stamped with the prompt version and hash that produced it, and drift fires an alert.
Everything audited
audit.mjs
One append-only row per route, gate, approval, pause, and budget halt.
Accepted-risk register
RISK_REGISTER.md
Known limits are logged with explicit revisit triggers, not quietly ignored.
